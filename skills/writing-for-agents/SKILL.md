## ⚠️ 副作用与边界（市场审核披露）

- **文件**：修改仓库中面向代理的文档
- **网络**：不直接访问外部网络
- **命令**：可能执行文档验证命令
- **凭据/敏感数据**：不接触凭据或敏感数据
- **人工确认**：所有高影响操作均由用户确认后执行。


写任何 Agent 要消费的文档——一个技能、一份 `AGENTS.md` / `CLAUDE.md`、一份由指针指向的文档——都参考这里。包装不同；写法相同：同样的杠杆让每份文档都可预测——Agent 每次运行走同样的*过程*，而不是产出同样的输出。

当你在写技能文档时，读 [`SKILL-MECHANICS.md`](SKILL-MECHANICS.md) 了解 frontmatter、调用方式选择和路由技能。

## 上下文指针

**上下文指针**是放在 Agent 上下文里的一个引用，它点名师某些上下文外的材料，并编码了触达它的条件。技能的 description 是一个；`AGENTS.md` 里点出一份文档的一行也是同一个东西。指针的*措辞*——不是它的目标——决定 Agent 何时触达材料，以及可靠性。一个必须触达的目标背后挂着一个措辞很弱的指针，就是一个"方差 bug"：先锐化措辞，只有锐化失败才把材料内联进去。

指针干两件事——说明材料是什么，并列出应该触发触达的**分支**（分支是文档处理的每个不同情形，不同的运行走不同的路径）。一个常驻加载的指针每个词在每一轮都要花钱，所以它比正文更值得修剪：

- **把主导词放最前面**——指针在触发工作上就是靠它发力。
- **每个分支一个触发器。** 给同一个分支改名的近义词是把一个分支写两遍；合并它们，只留真正不同的分支。
- **砍掉正文已经承载的身份信息。**

## 两种负载

你加的每一份文档和指针都在花两份预算之一：

- **上下文负载** — 常驻加载材料对 Agent 窗口的成本：`AGENTS.md` 里的一行、技能的 description、任何每轮都坐在上下文里、无论是否触发都在花 token 和注意力的东西。
- **认知负载** — 对人类花的成本：哪些文档存在、什么时候去拿哪个。人是索引。不是要最小化的成本——它是人类的能动性的代价；花在人类判断重要之处，搬走人类判断无关之处。

只通过指针触达的材料，以指针自己那一行为代价免于上下文负载；完全没有指针的材料，则全靠认知负载扛着。

## 信息层级

一份文档由两种内容构成——**步骤**（Agent 执行的有序动作）和**参考**（按需查阅的定义、规则、事实）——它们自由混合：全步骤（一份菜谱）、全参考（审查规则、本技能）、或两者兼有。核心决定是每一块材料坐在**信息层级**的哪一级——一把按 Agent 需要材料的紧迫程度排的梯子：

1. **文件内步骤** — 主层级：Agent 按顺序做什么。
2. **文件内参考** — 按需查阅。常见情形是合理扁平的同级集合（审查的每条规则在同一级）——是好的布局，不是坏味道。
3. **外置参考** — 推到独立文件，经上下文指针触达，仅当指针触发时才加载。从同文件夹的兄弟文件，到生活在任何地方、任何文档都能指向的完全外部参考，都属于这一级。

往下推得不够，顶层臃肿；推得太过，Agent 真正需要的材料被藏起来。这个张力就是全部的决定。

**渐进披露**是沿着梯子向下走——移出主文件、藏到指针后面——让顶层保持可读。主要不是 token 优化：这是层级被保护的方式。分支是最干净的披露测试：每个分支都需要的就内联，只有部分分支会触达的推到指针后面。当文档有步骤时，本该外置的文件内参考会掩埋它们，把"是否认真对待"变成掷硬币——不只是可读性的杠杆，更是方差的杠杆。

**共置**是文件内的伴侣：梯子决定一块材料放在*多深*，共置决定它落在那里后*旁边挨着什么*。把一个概念的定义、规则、注意事项放在同一标题下，而不是散落各处，读一部分就把它的邻居一起带进来。测试：文档读起来应该像给 Agent 写的文档——分组过的材料读起来像；散落的材料不像。（和重复不同：重复是把一个意思写两处；散落是把一个意思撕碎在好多处。）

**蔓延**是这里的失败模式：文档单纯太长，即便每一行都活着且唯一。注意力在被超额的部分上变稀，每多一行就多一行要保持相关。解药是梯子：把参考披露到指针后面，按分支或序列拆分，让每条路径只携带它需要的东西。

## 步骤与完成标准

每个步骤都有一个**完成标准**收尾——告诉 Agent 工作结束的条件。两个属性让它成为杠杆：

- **清晰度** — Agent 能分辨完成和没完成吗？模糊的界（"达成理解"）引来**过早完成**：在真正做完之前结束步骤，注意力滑向*结束*本身。可见的剩余步骤——**后置完成步骤**——提供拉力；标准的清晰度是阻力。按顺序防守：**先锐化边界**（局部且便宜）；只有边界不可约地模糊*并且*你观察到那个冲动时，才拆分序列把后面的步骤藏起来——而且隐藏要跨真正的上下文边界才有效（一次交接或一次子代理派发；内联调用会让后面的步骤留在上下文里，什么都清不掉）。
- **要求量** — 它要求多少。"每个被改动的模型都交代清楚"逼出扎实的工作，而"产出一份变更清单"不会。要求量驱动**跑腿**——Agent 在工作内部做的挖掘，潜藏在措辞里而不是写成独立步骤——而且不受步骤束缚："每条规则都应用"约束一份扁平参考，正如"每一步都做完"约束一个序列，这就是全参考文档仍然扛着穷尽性标尺的方式。

最强的标准既可核对又穷尽。

## 何时拆分

把一份文档拆成两份会花掉两种负载之一，所以只有当一切值得时才拆：

- **按序列** — 当后置完成步骤会诱惑 Agent 草草对待面前这个步骤时，拆开一连串步骤。让它们离开视线，能驱动更多针对当前任务的跑腿。当心反面：合并序列会让每个步骤后面的步骤暴露给接下来的内容，招来过早完成。
- **按调用方式** — 技能专属：见 [`SKILL-MECHANICS.md`](SKILL-MECHANICS.md)。

## 主导词

**主导词**是一个已经活在模型预训练里的紧凑概念，Agent 跑文档时用它思考（_lesson_、_fog of war_、_tracer bullets_）。作为 token 反复出现、从不展开成句子，它积累出分布式定义，用最少的 token 锚定一整块行为——靠征用模型已有的先验。自己造词也行，只要定义清楚，但造出来的词征用不到先验——你用定义 token 付的钱，预训练过的词是白送的；先找现成的词。

它锚定两次。正文里，*执行*：词每次出现，Agent 都伸手拿同样的行为；在扁平参考内部，它把注意力聚焦到一类要寻找的东西上。指针里，*调用*：当同一个词活在你的提示、你的文档、你的代码库里，Agent 把那份共享语言和材料连起来，触达得更可靠。

四处寻找用主导词重构的机会。三个地方都展开写的三件套、一个指针花一句话去指代一个想法——每处都是一段乞求坍缩成单个 token 的文字：

- "快速、确定、低开销" → _tight_（一个 _tight_ 循环）。
- "一条你信得过的循环" → _red_——一个模糊的门变成了二元可观察状态（循环在这个 bug 上变 _red_，或不变）。

你赢两次：更少的 token，以及一个更锋利的钩子让 Agent 挂思考。假设每份文档都背着主导词能退役的复述——去找它们。

**否定式**是这个杠杆旁边的失败模式：靠禁令来掌舵会把被禁的行为拖进上下文，让它*更*可用而不是更不可用。_别想大象_，大象就是一切；否定式是一个弱修饰语，被强激活的概念碾过，于是禁令有一半读起来像是让你去做那件事的指令。提示**正面**的东西——陈述目标行为（"写一行注释"），让被禁的那个从不被说出。一条禁令只有当它是你没法正面表达的硬护栏时才配存在；即便如此，也要和正面目标配对，让注意力落在"做什么"上。

## 修剪

- 每个意思只留**单一事实来源**：一个权威位置，改行为就是一处编辑。**重复**——同一个意思出现在多处——花维护和 token，还把某个意思在梯子上的显眼度抬到它真实等级之上。（主导词的反面事故：它故意重复 token，从不重复意思。）
- **环境**也是事实来源——`package.json` scripts、配置文件、目录布局、`--help` 输出——复述它的文档是**缓存**：一次查询的副本，只有查询很贵时才配得上它的负载。缓存 Agent 一眼找不到的东西：没写下来的惯例、某个选择背后的理由、没有配置会承认的坑。把一文件一命令的查询留给环境，在那里他们不会过期。
- 逐行检查**相关性**：它还和这份文档做的事有关系吗？一行失去相关性，要么是从来无关（纯展示，或本该外置的分支），要么是它所描述的行为或世界变了而它过期。短的文档更容易保持相关。没有修剪纪律，默认的命运就是**沉积**：因为"加"感觉安全、"删"感觉危险而沉淀下来的过期层，直到你必须一路凿穿它们才能找到还活着的东西。
- 逐句猎杀**空操作**：模型默认就会遵守的指令花着负载却什么都没说。测试——它相对默认改变了行为吗？——是相对模型的，不是相对读者的：两个人为一条空操作争执，争的其实是默认，靠跑文档来裁决，不靠辩论。一句没过测试，删整句，而不是从句子中删词。这个测试也给主导词打分：弱到打不过默认的词（Agent 已经够 thorough 了你再说 _be thorough_）是空操作，修法是换个更强的词（_relentless_），不是换种技术。
