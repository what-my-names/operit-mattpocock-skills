## ⚠️ 副作用与边界（市场审核披露）

- **文件**：生成 Bash 向导脚本（可提交仓库或 scratch）
- **网络**：打开第三方仪表板/网站 URL
- **命令**：执行 Bash 脚本、幂等写入 .env、写 gh secret/gh variable
- **凭据/敏感数据**：捕获凭据值写入 .env/secrets，密文输入，逐阶段人工确认
- **人工确认**：所有高影响操作均由用户确认后执行。


# Wizard

一个 **wizard** 是一个 bash 脚本，一步步引导人类走完一个手动流程——这个流程手工做很繁琐，而且每次都要向 AI 重新解释一遍。它打开每个 URL，说清楚要点什么、复制什么，捕获值，写到该去的地方（`.env`、GitHub secrets），每个阶段都确认，并显示还剩几个阶段。它可能配置第三方服务、跑一次一次性迁移，或者把项目从一个状态搬到另一个状态。

愉悦的 UX 已经由 [template.sh](template.sh) 解决了——逐阶段的进度、确认门、跨平台 URL 打开（含 WSL）、隐藏式密文输入、幂等的 `.env` 更新、`gh secret`/`gh variable` 写入、以及收尾摘要。**你的工作只是界定流程范围并撰写它的阶段。** `STAGES` 标记之上的库在每个 wizard 里都一模一样；一致性才是重点——永远不要手改它。

wizard 默认是一次性的——为一次运行而建，存到 scratch 或 `scripts/` 路径，活干完就删。只有当用户想要一条可重复的、该留在仓库里的配置路径时，才提交它。

## 流程

### 1. 界定流程范围

理清人类必须走的每一个手动步骤，以及沿途要捕获的每一个值。先读仓库——不要冷启动提问：

- 配置类：`.env`、`.env.example`、`.env.*`、`README`、`docker-compose*`、框架配置、以及 `.github/workflows/*`（每个 `secrets.*` / `vars.*` 引用都是 wizard 必须产出的值）。
- 迁移或切换类：当前状态、目标状态、以及两者之间不可逆的动作。

然后把阶段的有序列表和每个阶段产出的值给用户看，并确认——他们可能加、删或重排。

**完成标准：** 每个阶段都按顺序命名，且对每个捕获值你都清楚 (a) 人类从哪里拿到它，(b) 它写到哪（`.env`、GitHub secret、两者都写、或不写——有些阶段是纯动作），(c) 它是否是密文（隐藏输入）或公开的。

### 2. 描绘每个阶段的路径

对每个阶段，写出人类要走的精确路径：打开哪个 URL、在那里做什么、值显示在哪、填入哪个变量——例如"Dashboard → Developers → API keys → Reveal test key → 复制"。在你并不真正了解当前 UI 或确切命令的地方，如实说明并问用户或查文档——**绝不要编造可能不存在的步骤**。

**完成标准：** 每个阶段都能追溯到陌生人可照做的具体指令。

### 3. 编写 wizard

把 `template.sh` 复制到目标路径。把示例阶段换成每步一个 `stage`，按依赖顺序排。使用库助手——`stage`、`say`/`step`、`open_url`、`ask`/`ask_secret`、`write_env`、`set_secret`/`set_var`、`pause`/`confirm`——并把 `TOTAL_STAGES` 设为你写的阶段数。

保持模板设定的标准：先打开 URL 再要值，任何密文都用 `ask_secret`，每个持久化值都 `write_env`，只有 CI 真正需要的值才 `set_secret`，任何不可逆动作之前都 `confirm`。每个 `stage` 清屏让当前步骤独占视线——一个阶段只做一件聚焦的事，别让人类需要的东西滚出屏幕。不要动标记上方的库。

### 4. 验证并交付

- `bash -n <script>`；有 `shellcheck` 就跑。
- `chmod +x <script>`。
- 不要自己端到端跑它——它会开浏览器并阻塞在人类输入上。改为静态走查：步骤 1 的每个值都被捕获并落到步骤 1 说的地方，每个 `set_secret` 的名字都和 CI 里的 `secrets.*` 引用精确匹配。
- 告诉用户怎么跑它。如果这是可重复的配置路径，提交它并从 README 链接，让下一个人跑脚本而不是问 AI。
