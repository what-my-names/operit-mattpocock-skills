一个松散的想法的到来——对于一次代理会话来说太大了，并且笼罩在迷雾中：从这里到**目的地**的路还不可见。寻路的意义在于**找到**这条路，而不是径直冲向目的地。这项技能在仓库的问题跟踪器上把道路绘制成一张**共享地图**，然后一张一张地解决它的**决策票**——其解决方式是一项决策，而不是要执行的一段构建——直到路线清晰为止。

每次努力的目的地都不同，而命名目的地是绘图的第一个动作——它塑造每一张票。它可能是一份要交接并迭代的规范，一个在规划开始前要锁定的决定，或者像数据结构迁移这样的就地更改。地图与领域无关——工程工作、课程内容，什么形状合适都行。

## 计划，而不是执行

Wayfinder 默认是**规划**：每张票解决一项决策，当地图完成时路就清晰了——在有人真正去做那件事之前，没有什么再需要决定。想直接干活的冲动，通常是你已经走到地图边缘、该交接了的信号。一项努力可以在它的**注释**里覆盖这个默认——把执行带进地图本身——但没有这种声明时，就产出决策，而不是交付物。

## 按名字引用

每张地图和每张票都是一个 issue，因此它有一个**名字**——它的标题。在人类阅读的所有内容里——叙述、地图的"迄今决策"——都用名字引用它，永远不用裸 ID、编号或 slug。一整墙的 `#42, #43, #44` 是不可读的；名字一眼就懂。ID 和 URL 不会消失——名字包裹着它的链接——但它们待在名字**内部**，从不替代名字。

## 地图

地图是仓库问题跟踪器上的一个单独 issue，标着 `wayfinder:map` 标签——是规范产物。它的票是地图的子 issue。

地图是**索引**，不是仓库。它列出已经做出的决策，并指向保存细节的票；一项决策只住在一个地方——它的票——所以地图从不复述它，只给要点和链接。

**地图、子票、阻塞关系和前沿查询实际存放在哪里，因跟踪器而异。** 问题跟踪器应该已经提供给你。如果没有，告诉用户运行 `setup-matt-pocock-skills`。查阅跟踪器文档的"寻路操作"一节，看*这个*仓库如何表达它们。如果没有提供跟踪器，默认使用本地 Markdown 跟踪器。

### 地图正文

整个地图的低分辨率视图，每次会话加载一次。未关闭的票**不**列出——它们是通过查询找到的未关闭子 issue。

```markdown
## Destination

<到达地图尽头是什么样子——这次努力正在寻找的那份规范、那个决定或那次更改。一两行；每个会话在选择票之前都要先对照它定位。>

## Notes

<领域；每个会话都应查阅的技能；这次努力的既定偏好>

## Decisions so far

<!-- 索引——每个已关闭的票一行：足以判断相关性，需要细节时点链接放大 -->

- [<已关闭票的标题>](link) — <答案的一行要点>

## Not yet specified

<!-- 见"战争迷雾"：范围内的迷雾，但还无法开票；随着前沿推进而毕业 -->

## Out of scope

<!-- 见"范围之外"：被排除在目的地之外的工作；已关闭，永不毕业 -->
```

### 票

每张票都是地图的**子 issue**；跟踪器的 issue ID 是它的身份。它的正文是问题，大小以一次 100K token 的代理会话为限：

```markdown
## Question

<这张票要解决的决策或调查>
```

每张票都带着一个 `wayfinder:<type>` 标签——`research`、`prototype`、`grilling`、`task` 之一（见[票的类型](#票的类型)）。

会话要先**认领**一张票，才做任何工作——把它分配给自己，这样并发会话就会跳过它。那个指派人*就是*认领：一张开着、没被指派的票是无人认领的。

阻塞关系用跟踪器的**原生**依赖关系表达——这至关重要，因为它在跟踪器自己的 UI 里以可视方式呈现前沿，让人不开地图就能看到什么可做。只有缺乏原生阻塞的跟踪器才回退到正文约定。当阻塞某张票的所有票都关闭时，这张票**解除阻塞**；**前沿**是已解除阻塞、无人认领的未关闭子票——已知世界的边缘。

答案不是正文的一部分——它在解决时记录（见[顺着地图推进](#顺着地图推进)）。解决票时创建的资产从 issue 链接出去，而不是粘进去。

## 票的类型

每张票要么是**HITL**——有人在环，和一个为自己发言的人一起工作——要么是**AFK**，由代理独自驱动。HITL 票只能通过那次实时交流解决；代理绝不能替人类发言（一个能回答自己问题的审讯代理就破坏了这一点）。

- **研究（Research）**（AFK）：阅读文档、第三方 API 或知识库等本地资源，摸清一项决策在等的事实。由一个用 "research" 调用 Skill 工具的子代理解决。需要当前工作目录之外的知识时使用。
- **原型（Prototype）**（HITL）：通过用 "prototype" 调用 Skill 工具，做出一个廉价、粗糙、具体的产物供人反应——大纲、潦草草稿、桩子，或 UI/逻辑代码——以此提升讨论的保真度。把原型作为资产链接出去。当"它应该长什么样"或"它应该如何表现"是关键问题时使用。
- **审讯（Grilling）**（HITL）：对话。默认情况。始终调用 Skill 工具两次，分别是 "grilling" 和 "domain-modeling"。
- **任务（Task）**（HITL 或 AFK）：在做出*决定*之前必须完成的手动工作——没什么可决定的、没什么可原型的、也没什么可研究的，但讨论被卡住直到它完成。注册一个服务以便评判它的 API、开通访问权限、搬动数据以便看清它的形状。这是唯一"做"而不是"决定"的类型——它靠解除一个决定的阻塞来赢得位置，而不是靠交付目的地。代理能独自完成的就独自开（AFK）；否则给人类一份精确的清单（HITL）。工作完成即解决；答案记录做了什么、以及后续票依赖的任何事实（凭据位置、新 URL、行数）。

## 战争迷雾

地图是*故意*不完整的：画不出你还没看见的东西。在存活的票之外有**战争迷雾**——你能感觉到有些决策和调查正要到来，但还钉不死它们，因为它们挂在仍未解决的问题上。解决一张票就推开它前方的迷雾，把现在能具体化的东西毕业成新票——一次一张，直到通往目的地的路清晰、再无票剩余。

地图的**尚未指定**一节就是记录那段昏暗视野的地方：疑似的疑问、之后要回访的区域。它是朝目的地去的未发现的前沿——这里的一切都在范围内，只是还不够清晰、开不了票。视野允许写多松就写多松、允许多全就写多全；它也兼任一块路标，让协作者读到这次努力在往哪个方向走。

**迷雾还是票？** 测试标准是你现在能不能把问题精确地陈述出来——*不是*你现在能不能回答它。

- **能精确陈述就开票**——哪怕它被阻塞着、你还不能动手。
- **还没法陈述得那么精确，就留在"尚未指定"**。不要把迷雾预先切成票大小的块：它比票更粗粝，而且一旦前沿推进过来，一块迷雾可能毕业成好几张票，也可能一张都没有。

**尚未指定**排除已经决定的东西（迄今决策）、已经是活跃票的东西、以及范围之外的东西（下一节）。

## 范围之外

迷雾只朝目的地聚集。目的地固定了范围，所以目的地之外的工作就是**范围之外**——它不是迷雾，也不属于**尚未指定**。它在地图上有自己的**范围之外**一节：你刻意排除在*这次*努力之外的工作。让一件事落在这里的是范围，不是清晰度。

范围之外的工作永不毕业——前沿停在目的地——所以只有目的地被重绘时它才会回来，而且那时它是一项新的努力，不是旧事的续作。

把某件事裁出范围是一种划定范围的行为，不是路线上的一个步骤。当一张已存在的票被发现落在目的地之外——绘图时误划进来，或某次解决把它暴露出来——**关闭它**（关闭的票明确地离开前沿），并在**范围之外**一节留一行：要点加为什么出界，链接到那张已关闭的票。它不进**迄今决策**，那里记录的是实际走过的路线——一条范围边界不是上面的一个步骤。

## 调用方式

两种模式。无论哪种，**每次会话解决不超过一张票**——唯独研究票例外。

### 绘制地图

用户带着一个松散的想法调用。

1. **命名目的地。** 调用 Skill 工具两次，分别是 "grilling" 和 "domain-modeling"，钉死这张地图要找的是什么——规范、决策或更改。目的地决定范围，所以先解决它。
2. **绘制前沿。** 再次审讯，这次**广度优先**：在整个空间里铺开，而不是在任何一条线上深挖，浮出未决的决策和现在就能迈出的第一步。**如果这轮没有浮出任何迷雾**——到目的地的路已经清晰，整个旅程小到一次会话装得下——你不需要地图。停下来问用户想怎么进行。
3. **创建地图**（标签 `wayfinder:map`）：填好 Destination 和 Notes，Decisions-so-far 留空，把迷雾草绘进**尚未指定**。
4. **创建你现在能具体化的票**，作为地图的子 issue——然后在**第二轮**接上阻塞边（issue 需要先有 ID 才能互相引用）。接线后它们分成前沿和被阻塞的；所有你还没法具体化的都留在迷雾里——**尚未指定**一节。
5. **发射研究子代理。** 对你刚创建的每张 `research` 票，启动一个子代理，用 "research" 调用 Skill 工具并行解决，在一次性 `research/<name>` 分支上捕获它的发现，并从票上留一个上下文指针。
6. 停——绘图是一次会话的活；它不亲手解决任何东西。

### 顺着地图推进

用户带着一张地图（URL 或编号）调用。票是**可选的**——没有指定票时，你来选下一个决策，而不是用户。

1. 加载**地图**——低分辨率视图，不是每张票的正文。
2. 选票。用户指了哪张就用哪张。否则按顺序取第一张前沿票。**认领它**：在任何工作之前把它分配给自己。
3. 解决它——**按需放大**：按需抓取任何相关或已关闭票的完整正文；为 `## Notes` 块点名的技能调用 Skill 工具。拿不准时，调用 Skill 工具两次，分别是 "grilling" 和 "domain-modeling"。
4. 记录解决：把答案作为**解决评论**发布，**关闭** issue，并把一个上下文指针**追加**到地图的迄今决策。
5. 添加新浮出的票（先创建后接线）；把答案已使其可具体化的任何迷雾毕业，从**尚未指定**里清掉每一块已毕业的迷雾，让它只以新票的形式存在。如果答案显示一张票（这张或另一张）落在目的地之外，**把它裁出范围**，而不是在路线上解决它。如果这个决定让地图的其他部分失效，更新或删除那些票。

用户可以并行跑已解除阻塞的票，所以预期其他会话会同时编辑跟踪器。
