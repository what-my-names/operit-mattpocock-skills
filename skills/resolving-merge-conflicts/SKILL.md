## ⚠️ 副作用与边界（市场审核披露）

- **文件**：直接修改仓库文件解决合并冲突
- **网络**：不访问外部网络
- **命令**：执行 git checkout/rebase/add 等 Git 命令
- **凭据/敏感数据**：不接触凭据或敏感数据
- **人工确认**：所有高影响操作均由用户确认后执行。


1. **查看合并/变基的当前状态。** 检查 git 历史与冲突文件。

2. **找出每处冲突的关键来源。** 深入理解每处修改的原因和本意。读提交消息，查 PR，查最初的 issue/票证。

3. **逐处解决。** 尽量同时保留双方意图。若无法兼容，选择与本次合并既定目标相符的一方，并记下取舍。**不要**发明新行为。始终解决到底；绝不 `--abort`。

4. 找出项目的**自动检查**并运行——通常先类型检查，接着测试，最后格式化。修复合并破坏的所有东西。

5. **完成合并/变基。** 暂存全部内容并提交。如果是变基，继续变基流程直到所有提交都变基完毕。
